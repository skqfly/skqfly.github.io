# Trilium 仅用于博客文章

Trilium / Trinote 只管理文章、文章封面和正文图片。动态、相册、友链、项目、首页和站点设置由 GitHub / App 管理。旧网页全站管理面板已停用，请使用原生文章目录。

## 编辑与发布

1. 打开“文章 Blog”，编辑原文章；新文章使用“文章模板”，不要克隆已有正文。
2. 在标题下方填写发布日期、作者、摘要和分类。文章正文使用 Markdown，保留数学公式。
3. 图片放入“图片素材 Media”，通过“选择图片”关系选择封面。正文可使用 `![说明](trilium:图片笔记ID)`；文章下的图片子笔记也会收集。
4. 保存后打开“提交发布”。未提交的修改不会随其他文章发布。旧文章也可更新 `publish` 标签值提交。
5. 打开 GitHub 的 `trilium-sync.yml` 工作流并 Run workflow，或等待定时队列检查。保留原有博客发布按钮、请求处理器和私有配置；不要重新安装旧全站面板。
6. 下架时打开“从网站下架”并提交；恢复时关闭后重新提交。原文保留，直接删除笔记不会删除线上文章。
7. “同步日志”保留阶段、字段错误、文件变化、GitHub 步骤和部署回执。成功后仅确认本轮未被再次编辑的文章请求。

## 同步所有权与媒体保留

同步只写 `src/content/posts/*.md`、`trilium/published.json`、`trilium/signals.json` 和文章引用的 `public/trilium-media/*.webp`（包括 480/960 预览）。不写 `src/data/site.json` 或 `src/data/photo-library.json`，不触碰 `public/photos/`。

`published.json` 的 `site`、`photos`、`ids` 是旧迁移历史，继续保留以免丢信息；它们不是网站数据源，不能据此回填 GitHub / App 内容。仅 `posts`、`signals`、`assets` 用于博客增量发布。非文章记录在收集、队列、选择、应用和输出阶段均被隔离。

共享媒体禁止自动垃圾清理：旧图片可能被 App 动态、相册或其他页面使用，快照无法枚举全部消费者。文章下架也不删除 WebP 文件。保留已有图片素材目录和原图；清理远端旧分类之前先备份，并确保没有移动或删除文章所需图片。

## App / GitHub 发布约定

- 动态：修改 `src/data/site.json` 内的 `talksPageContent.entries`；保留其他站点字段。每条记录是 `{ id, title, date: "YYYY-MM-DD", description, images: Photo[] }`。
- 相册：修改 `src/data/photo-library.json` 对象，键是稳定照片 ID。`Photo` 为 `{ src, width, height, alt, preview, previewLarge }`；图片可以提交到 `public/photos/*.jpg`，公开 URL 是 `/photos/文件名.jpg`。使用同一 URL 作三个图像字段可兼容现有组件，也可另传缩略图。
- 动态与相册中的图片元数据按值存储；动态只发布配图不必加入相册。已有共享图片路径继续有效，不要覆盖或删除未知引用的媒体。
- 一次发布的 JSON 与媒体通过 Git Trees / Commits / Refs API 原子提交到 `main`，以当前分支 HEAD 为父提交并处理冲突；GitHub OAuth 提交触发既有 `deploy-pages.yml`。App 无需触发 Trilium 同步或写 Trilium 清单。
- Photos 页面和灯箱不显示图片说明文字，`alt` 和按钮无障碍标签继续保留。`alt` 不应被用作可见标题或图注。

## 验证与凭据

`npm run trilium:check` 运行发布规则测试；`npm run build` 进行 Astro 检查和静态构建。
`npm run trilium:preview` 读取远端并预览；`npm run trilium:sync` 写本地文件。两者需要 `TRILIUM_SERVER_URL` 和 `TRILIUM_ETAPI_TOKEN`，不自动推送。凭据只放环境变量或 GitHub Secrets。
